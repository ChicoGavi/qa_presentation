¿Qué es y qué problema resuelve?

¿Qué es?

Concepto Base

Es la administración estratégica de todo el proceso de pruebas.

Crea un "hilo conductor" (trazabilidad) que conecta directamente lo que el cliente pidió, las pruebas que diseñamos y los errores que encontramos.

¿Para qué sirve?

Uso en la empresa

  • ✓Medir la cobertura de pruebas en el sistema.
  • ✓Tomar decisiones basadas en datos reales.
  • ✓Auditar la calidad del software con precisión.

Problema

Elimina el caos

Evita incertidumbre como:

"¿Alguien probó el login?"
"¿Por qué este bug llegó a producción?"

  • •Previene duplicar esfuerzos.
  • •Brinda visibilidad total.

¿En qué momento del proceso se utiliza?

01

Fase de Análisis

REQUISITOS

Al recibir las Historias de Usuario, se inicia la matriz de trazabilidad.

02

Fase de Diseño

CASOS DE PRUEBA

Al escribir los Casos de Prueba y enlazarlos directamente a los requisitos.

03

Fase de Ejecución

PRUEBAS Y BUGS

Al correr las pruebas y enlazar los Bugs encontrados a los Casos de Prueba.

04

Fase de Cierre

GO / NO-GO

Al revisar la Matriz de Trazabilidad para decidir si se lanza el producto.

Herramientas y Ejemplo Práctico

🛠️ Ecosistema Integrado: GitHub // Microsoft Excel / Word
01

HERRAMIENTAS

GitHub // Microsoft Excel/Word

Sistemas donde llevamos los Requisitos, Pruebas y Bugs para realizar un seguimiento adecuado.

¿Cómo se complementan?
• Excel / Word: Matriz de Trazabilidad (RTM) formal y diseño detallado de casos.
• GitHub: Control de Issues, ramas, Pull Requests y tablero de equipo en GitHub Projects.

Otras: Jira + Xray, Azure DevOps, ALM Octane.

EJEMPLO PRÁCTICO

Flujo de Trazabilidad

  • •Requisito: El usuario debe poder retirar el producto.
  • •Ejecución: Se crean 2 Casos de Prueba. 1 falla y se reporta un Bug.
Requisito Caso Prueba Escenario Resultado Issue GitHub
REQ-05 CP-008 Remover desde carrito (/cart.html) ✓ PASS —
REQ-05 CP-009 Remover desde vista Products ✗ FAIL #112 BUG-04 (P1)

Impacto / Resultado

Estado del Requisito: "Fallido / Prioridad P1".

La matriz visibiliza la falla, evitando liberaciones con errores críticos hasta que el Bug sea resuelto, en GitHub se lleva seguimiento de los avances, una vez resuelto se da la viabilidad para continuar con la liberación.

Creación de Issue #105 (REQ-05) en GitHub Projects
